# pet-kit 0.2.0 候选验收

2026-10-12。基线 `09df6b578e717448abaea9aa854e6898b1be28d1`，独立分支 `codex/internet-play`；未公开推送、合并或发布。

## 实现

- 真实双人 sessions 不接受多人 to 寻址、事件也没有 from；Room 从 context 区分双人/多人，双人映射唯一对端。原多人默认 API 不变。
- `appearancePolicy: 'continuous'` 供黄金矿工显式启用局内形象更新；默认仅大厅传素材。当前签名和缓存独立，慢传输完成不能令游戏回退到旧形象，切回缓存不再次传输。
- 对启动、poll、素材读取/传输、解包等异步边界检查 dispose；连接回调中同步销毁不会重建计时器。重连恢复 online 后立即通知大厅消费者。
- vendor 导出版本/源码摘要与独立校验器，消费仓库构建只读取固定副本。内部导入或修改副本会失败，不能通过读取同级 main 偷偷升级。

## 验证

显式提供实际宿主 `PET_HOST_ROOT`，最终 `npm test` 对应完整套件 **25/25，0 跳过**，证据 `artifacts/final.tap`。其中真实 manager/shared SDK 双人测试走生产校验/轮询/素材模块，底层双向线仍是内存连接；不冒称实体网络验证。原多人用例、连续形象、生命周期与 vendor 验证都已挂入 npm test，并各有具名入口。

黄金矿工使用实际导出的 0.2.0 副本，适配回归 13/13；规则回归 29/29；真实隐藏桌宠 LAN 完整流程通过，带动画私人构建/公开构建各有产物验证。中转/云端最终证据由黄金矿工独立分支的 `docs/internet-play-validation.md` 记录。宿主继续使用既有未发布候选；本轮没有新增宿主 SDK，三个公开 SDK 仓库均逐项核对后无需改动，见本地 `artifacts/sdk-compatibility-review.json`。

现有消费者只在临时副本替换 vendor，不改正式仓库：水球原基线 `ebf28c6b` 的 net 回归 **4/4 通过**（169.2 秒），含完整三人/电脑多轮对局。坦克原基线 `3cb1a867` 位于另一任务分支，清醒后的完整原 net 回归 **4/4 通过**（118.2 秒）；三端关卡结果/地形/死亡一致、限速状态年龄、离开接管、客人判定躲避均通过。只在临时副本增加超时诊断，未改变玩法、等待门槛或断言。两消费者合计 8 项通过，不代表它们的真实公网 E2E 已验收。

## 发现与限制

- 开发阶段真实双人契约首先失败，修复后通过；确保以后不会只用多人 fake 证明双人支持。
- 交叉审查分别复现在线通知漏发和启动中销毁后重建计时器，均保留红→绿证据。
- 原多人时钟用例在随机 5–55ms 延迟下有一次偏差 26ms，超过 <25ms 的断言；未放宽标准，单测复跑和最终完整套件通过。失败仍保留为测试稳定性限制，不以一次通过宣称任意负载下精度。
- 坦克初次自然关卡回归与一次黄金矿工 E2E 跨越了本机合盖休眠（约237秒），因此该批次无有效兼容结论，保留中断证据后重跑，不修改游戏断言。
- 本轮只交付黄金矿工接入；不会自动升级水球/坦克或宣称所有游戏公网验收完成。发布其他消费者前仍须它们各自的真实游戏 E2E。
